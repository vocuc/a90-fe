===========================

- Câu 21: đã thử tay, TikTok Studio bản web lưu nháp được bài ảnh.

1. LUỒNG
--------
Tạo bài (từ lô / ảnh đã có) -> sửa tiêu đề, nội dung, hashtag, ảnh -> bấm "Đăng lên TikTok"
-> backend lưu chỉnh sửa, tạo job tiktok_publish, bài sang queued
-> worker TikTok nhận job (bài sang publishing), tải ảnh, mở TikTok Studio, điền nội dung, LƯU NHÁP
-> worker báo completed: bài sang published ("Đã lưu nháp TikTok"), A51 dừng theo dõi tại đây.
   Admin / nhân viên tự vào TikTok đăng nháp, không cập nhật lại A51.
-> worker báo failed / quá lease: bài về pending_review + last_error, người dùng tự bấm đăng lại.
   Không tự giao lại cho worker khác.

2. TRẠNG THÁI BÀI
-----------------
  pending_review  Chờ gửi              chưa bấm đăng (hoặc lần đăng trước lỗi, có last_error)
  queued          Chờ đăng             đã có job, chưa worker nào nhận. Chờ mãi đến khi có worker (không hết hạn)
  publishing      Đang đăng            worker đã nhận job
  published       Đã lưu nháp TikTok   worker lưu nháp xong (published_at = lúc đó)
  (generating giữ cho trường hợp bật AI viết nội dung, như hiện tại)

- queued / publishing: khoá hoàn toàn, không sửa, không huỷ, không xoá (409).
- Lỗi chỉ có MỘT thông báo chung: last_error = { code: "TIKTOK_PUBLISH_FAILED",
  message: "Đăng thất bại, vui lòng thử lại." }. Mã lỗi chi tiết của worker backend chỉ lưu log cho admin.
- Không tính phí, không giới hạn số bài, không có link bài TikTok.

3. BACKEND
----------
a) Bỏ toàn bộ TikTok API: OAuth (GET/DELETE /tiktok/account, POST /tiktok/oauth/authorize, callback),
   webhook, Content Posting API, cột tiktok_publish_id; /auth/me bỏ trường tiktok.
b) Bảng mới tiktok_accounts (id, name, username, is_active), admin thêm / sửa / tắt ở trang admin.
   Admin gắn tài khoản cho từng worker (worker token). Worker chưa gắn tài khoản / tài khoản bị tắt thì không
   nhận được job tiktok_publish.
c) POST /tiktok/posts/{id}/publish: body như cũ { title, content, hashtags, images }. Chỉ nhận khi bài đang
   pending_review (khác -> 409). Lưu chỉnh sửa, tạo job, bài sang queued. Trả { data: TikTokPost }.
d) Job (GET /jobs, worker gửi ?types=tiktok_publish):
     { "id": 130, "type": "tiktok_publish",
       "request": { "post_id": 55, "images": ["https://... (link ký số, theo thứ tự, ảnh đầu là bìa)"],
                    "title": "...", "content": "...", "hashtags": ["a51", ...] } }
   Link ảnh phải còn hạn đủ lâu cho worker tải (link ký số hiện ~15 phút: cấp lúc worker nhận job).
   Khi worker nhận: bài -> publishing, ghi tiktok_account_id = tài khoản của worker.
e) POST /jobs/{id}: completed (không cần file) -> published; failed (error_code, error_message) -> pending_review
   + last_error chung. Quá lease -> failed luôn, không giao lại.
f) TikTokPost: bỏ tiktok_username; thêm trạng thái queued. Admin xem được tiktok_account của bài.

5. FLOWKIT
----------
Worker mới (vd tiktok_worker.py) dùng chung claim_job / submit với ImageGenerate.py, GET /jobs?types=tiktok_publish.
Chrome profile riêng đã đăng nhập sẵn tài khoản TikTok của worker. Tải ảnh -> TikTok Studio -> chọn ảnh, điền
tiêu đề / nội dung + hashtag -> Lưu nháp -> báo completed. Lỗi (đăng xuất, captcha, upload lỗi...) -> failed
với error_code riêng để admin xem log.
